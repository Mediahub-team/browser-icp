# Этап 0 — Описание продукта

Вход для всего пайплайна. Качество ICP, офферов и результатов **упирается в качество этого
этапа**. Поэтому этап 0 — не одна заметка, а под-пайплайн из четырёх артефактов, построенный
на принципе **функциональность ⟂ позиционирование** (см. [`../PLAN.md`](../PLAN.md) §2.0).

```
0.1 product-functionality.md   что продукт умеет (стабильная база)   ─┐
0.2 product-positioning.md     угол продвижения (форкаемая переменная) ─┼─→ 0.5 market-landscape.md ─→ 0.9 product-description.md → этап 1
                                                                        ┘   (исследование под угол)     (синтез: вход для ICP)
```

| Под-шаг | Артефакт | Шаблон |
|---|---|---|
| 0.1 Функциональность | `product-functionality.md` | [`../templates/product-functionality-template.md`](../templates/product-functionality-template.md) |
| 0.2 Позиционирование | `product-positioning.md` | [`../templates/product-positioning-template.md`](../templates/product-positioning-template.md) |
| 0.5 Ландшафт рынка | `market-landscape.md` | [`../templates/market-landscape-template.md`](../templates/market-landscape-template.md) |
| 0.9 Описание продукта | `product-description.md` | [`../templates/product-description-template.md`](../templates/product-description-template.md) |

> **Развилки видения.** Сменить угол продвижения = форкнуть **0.2 позиционирование** (и всё
> ниже по течению) в ветку `cycle/<vision>` или `s0/<slug>`, переиспользуя 0.1 без изменений.
> Так одна функциональность проверяется под разными обещаниями. См. [`../BRANCHING.md`](../BRANCHING.md).

> **Вход этапа 0 (seed).** Пайплайн засевается двумя внешними входами от человека: (1) **знание о
> продукте** → 0.1 функциональность (инварианты + палитра); (2) **угол-позиционирование на
> проверку** → 0.2. Функциональность — стабильный референс, **угол ведёт** ([`../PLAN.md`](../PLAN.md)
> §2.0); 0.5 и 0.9 — производные. Смена угла = форк `cycle/<vision>`; эволюция функциональности
> (впитывание фич из офферов) = итерация `version/<version-name>` (см. [`../BRANCHING.md`](../BRANCHING.md)).

---

### 0.1 — Промпт генерации функциональности
> Опиши **что продукт способен делать**, строго по шаблону `templates/product-functionality-template.md`,
> в двух слоях: **инварианты** (жёсткие границы, истинные при любом угле, — связывают downstream и
> порождают гипотезы) и **палитра функций** (обобщённые классы возможностей). Только факты о
> механике — **без ценностных формулировок, обещаний и выгод** (уйдёт в позиционирование), **без
> статуса реализации** (`✅/◐/⬜`, «в разработке», «mock») и без текущих настроек механики (статус
> смещает downstream). Ограничения формулируй как **feasibility** (надёжно/выполнимо ли), а не
> «построено ли». Если новая итерация впитывает возможности из офферов — занеси их в §7 со ссылкой
> на оффер-источник (петля 7→0, см. [`../BRANCHING.md`](../BRANCHING.md) §4).

### 0.2 — Промпт генерации позиционирования
> **Угол — это seed цикла** (даётся человеком в промпте, см. «Вход этапа 0» выше). Здесь его
> формализуют по шаблону `templates/product-positioning-template.md`, **сверяя с 0.1**: угол обязан
> уважать **инварианты** (обещать против них нельзя), свободно черпает из **палитры** и **может
> требовать возможностей, которых в палитре ещё нет** — это нормальный тест спроса. Зафиксируй
> единственный исследуемый promise, какую функциональность выводим вперёд / прячем, ценностную
> рамку («покупают изменение»), точку отсчёта, допущения цикла. Один файл = один угол; второй
> угол — отдельная ветка (форк `cycle/<vision>`), не второй абзац.

### 0.5 — Промпт генерации ландшафта рынка
> Испытай угол из `product-positioning.md` о реальный рынок РФ по шаблону
> `templates/market-landscape-template.md` — **не подтверди, а проверь на прочность**. Сначала
> **таксономия конкурентов** (все классы способов получить тот же результат — банки, МП, агрегаторы,
> операторские/телеком-программы, кешбэк-по-чекам, расширения, экосистемные подписки, …), потом
> разбор. **Доминирующего конкурента декомпозируй** на суб-механики и сравнивай угол с **сильнейшей**.
> Исследуй: похожие фичи, размер/**динамику** (растёт/сжимается), **сбалансированный VoC** (довольные
> + недовольные, дословно), поведение/каналы (**готовность переключаться**, не только оффер
> конкурента), ценообразование, регуляторику, доверие/антифрод. **Обязателен раздел
> «дисконфирмирующие данные / почему ставка может не сыграть»** с kill-criteria — целенаправленно
> ищи опровержение. Каждый факт — со ссылкой; неопределённость — явно. В конце импликации + какие
> kill-criteria этап 1 проверяет первыми.

### 0.9 — Промпт генерации описания продукта
> Синтезируй `product-functionality.md` + `product-positioning.md` + `market-landscape.md` в
> вход для ICP по шаблону `templates/product-description-template.md`: (1) проблема, (2)
> ценность, (3) ключевые фичи, (4) контекст рынка и отстройка, (5) монетизация, (6) стадия и
> ограничения, (7) целевая рамка/границы, (8) константы vs гипотезы, (9) открытые вопросы к
> аудитории. Раздел «Ценность» — важнее списка фич. Каждый тезис помечай `validated` (опора
> на ландшафт) или `untested` (допущение).
