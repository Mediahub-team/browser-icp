# Функциональность продукта — Кэшбэк Браузер (под-этап 0.1)

> **Что это.** Описание того, **что продукт умеет**, безотносительно того, как мы его
> продаём. Стабильная база этапа 0: одна и та же функциональность переиспользуется разными
> [[product-positioning|позиционированиями]] без изменений (принцип «функциональность ⟂
> позиционирование», [[PLAN]] §2.0). Здесь — **полная** карта возможностей, даже тех модулей,
> которые текущий угол продвижения не выводит вперёд.
>
> **Без ценностных формулировок** — только факты о механике, статусе реализации, стадии и
> ограничениях. Обещания и выгоды — в [[product-positioning]].

> **Источник истины — фактическая сборка** (что закодировано в iOS-приложении и backend), а не
> идеализированная механика угла. Расхождения сборки и угла помечены в §9.

## 0. Краткая карточка
- **Slug / продукт:** Кэшбэк Браузер (КБ), `cashbackbrowser`.
- **Технически одной строкой:** iOS-браузер на WKWebView с встроенным ИИ-агентом, анализатором
  товаров, кросс-маркетплейс-сравнением и геймифицированной кешбэк-программой.
- **Платформа и рынок:** iOS (Swift/SwiftUI), Россия, русскоязычные маркетплейсы.
- **Стадия сборки в целом:** ранний продукт / pre-launch, не опубликован в App Store; ядро
  ИИ/анализа работает, backend кешбэка и вывода — в разработке (локальный mock).

## 1. Назначение и границы продукта
**Что продукт делает.** Полноценный мобильный браузер, поверх которого работают: (а) ИИ-агент,
отвечающий по контексту открытой страницы и умеющий искать/читать веб и маркетплейсы; (б)
анализатор товаров Ozon (отзывы, продавец, листинг, итоговая оценка); (в) кросс-МП сравнение
цен (WB, Яндекс Маркет); (г) кешбэк-программа с геймификацией (начисления, задания, ежедневный
бонус, колесо удачи, вывод на карту-партнёр).

**Что продукт НЕ делает (границы).**
- **Не отслеживает покупки вне браузера КБ** — нативные приложения МП, оплата через СБП/банк-
  приложение вне поля видимости. Кешбэк возможен только за покупки на сайтах, открытых внутри КБ.
- **Полный анализ товара — только Ozon.** WB и Яндекс Маркет доступны лишь для поиска/сравнения,
  не для разбора карточки. Lamoda и SberMegaMarket в анализаторе не поддержаны.
- **Нет работающего backend** для баланса кешбэка, заданий и вывода средств — сейчас mock.
- **Не персистит открытые вкладки** между запусками (история диалогов — персистится).

**Зона исследования цикла.** Какую часть этой функциональности выводит вперёд текущий угол —
определяет [[product-positioning]]; что вынесено за скобки в цикле v3 — см. §8.

## 2. Константы механики (не гипотезы)
- **Кешбэк — только за покупки на сайтах, открытых внутри браузера КБ.** Технически нельзя
  отследить то, что прошло мимо браузера → это жёсткая граница, а не настройка.
- **Двухфазное начисление:** покупка → статус «Проверяем» → «Подтверждено». Антифрод-гейт перед
  зачислением в доступный баланс.
- **Вывод — только на карту-партнёр** (Газпромбанк), с минимальным порогом (цель от 600 ₽).

## 3. Карта функциональности (модули и возможности)

**A. Браузер (носитель) — ✅.** Вкладки (до 5) с визуальными превью в переключателе; адресная
строка с поиском и кнопками назад/вперёд/обновить; быстрые ссылки на 5 МП (Ozon, Wildberries,
Lamoda, Яндекс Маркет, SberMegaMarket); кнопки перехода в меню кешбэка и вызова ассистента (✦);
индикатор накопленного кешбэка; автоскрытие тулбара при скролле вниз; **подавление баннеров
«открыть в приложении»** на сайтах МП; обработка `target="_blank"` внутри того же таба.

**B. Поделиться → открыть в КБ — ✅.** Расширения «Поделиться» и «Действия» (пункт «Кэшбэк
Браузер» в системном share sheet iOS). Ссылка открывается в новой вкладке; текст — как
Яндекс-поиск. Реализовано через custom URL scheme `cashbackbrowser://open` + DeepLinkRouter
(`.onOpenURL`), без App Group.

**C. Анализ товаров (Ozon) — ✅ (только Ozon).** Пайплайн: определение product ID из URL →
инъекция JS-коллектора `ozon-collector.js` (перехват API Ozon, сбор отзывов, характеристик,
данных продавца) → отправка на backend `/ingest` → SSE-стриминг отчёта с пошаговым прогрессом.
Анализируются: отзывы (статус ok/warn/suspicious/no_data, распределение оценок, примеры),
продавец (рейтинг, возраст, объём продаж, % возвратов/отмен, жалобы), качество листинга
(фото/видео/описание/характеристики), итоговая оценка 0–10 с цветовым вердиктом и плюсами/минусами.

**D. Кросс-маркетплейс сравнение — ✅ (WB, Яндекс Маркет).** Скрытые WKWebView для WB и ЯМ;
JS-коллекторы (`wb-search-collector.js`, `ym-search-collector.js`); параллельный поиск с
таймаутом 18 сек и fallback на DOM-скрапинг; backend `/compare` с ИИ-саммари и матчингом по
топ-10; карточки товаров (изображение, цена, рейтинг, ссылка).

**E. ИИ-ассистент — агент с инструментами — ✅.** Агентный цикл на Claude Sonnet 4.5 (OpenRouter
→ Cloudflare AI Gateway): модель сама выбирает инструменты, до 6 итераций за ход. SSE-стриминг
токенов и статусов (`token / tool_started / tool_call / tool_result / done`). Контекст хода:
маркетплейс, URL, заголовок, данные товара, фрагмент текста страницы (~1500 симв.).
Markdown-рендеринг, «думающий» бабл, retry при сбое стрима, ссылки в новой вкладке. Вызов
кнопкой ✦ из тулбара (автопроброс контента текущей страницы), отдельный экран, история диалогов.

**E.1. Инструменты ассистента (6 тулов) — ✅.** Клиентские исполняются на iOS через скрытые
WKWebView, серверные — на backend:
- `search_current_marketplace` / `search_other_marketplaces` — поиск на текущем / других МП (клиентские, параллельно);
- `query_our_product_db` — база проанализированных товаров в ClickHouse с кэш-вердиктами (серверный);
- `general_web_search` — веб-поиск через Yandex Cloud Search API; `mode=shopping` биасит на МП (серверный);
- `extract_current_page` — полный текст открытой страницы для саммари (клиентский);
- `fetch_and_extract_url` — открыть произвольный URL: публичные страницы через markdown.new (−~80% токенов), сессионные домены и фолбэк — фоновый WKWebView (клиентский).

**E.2. UI ассистента — ✅.** Карточки статуса инструментов (что агент делает сейчас); чипы-
источники под ответом (favicon + домен, тап → новая вкладка); саджесты на стартовом экране
(LLM под контекст страницы — Gemini Flash, `/agent/suggestions`, фолбэк на пул готовых); карточки
и карусель найденных товаров; кнопка «Репорт» с категориями → `/agent/report`.

**E.3. История диалогов — ✅.** Локальная персистентность (`LocalChatRepository`); экран истории
с поиском, переименованием и удалением диалогов.

**F. Кешбэк-программа — ◐ (UI/логика на mock, backend ⬜).** Состояние хранится локально в
`cashback.json` (Documents), переживает перезапуск; backend пока нет.
- Кешбэк за покупки: % зависит от категории товара; начисление «Проверяем» → подтверждение.
- Ежедневный вход: +5…15 ₽, 7-дневный стрик.
- Задания: первая покупка +200 ₽, браузер по умолчанию +20 ₽, вход в аккаунты на 5 сайтах +100 ₽.
- Колесо удачи: 2 спина в час, призы — промокоды партнёров.
- Вывод: на карту Газпромбанка, цель от 600 ₽ (backend в разработке).
- Прогресс к цели вывода, история операций с фильтрами (все/покупки/бонусы/выгоды), поздравительные sheet'ы.

**F.1. Кешбэк-страница — ✅ (на mock-данных).** Накопленный кешбэк (накоплено / целевой порог
вывода); кнопки: выпуск карты-партнёра, активация ежедневного бонуса, переход в колесо удачи;
список заданий; раскрываемая история операций по группам.

**G. Онбординг (первый запуск) — ✅.** 3 экрана (кешбэк рублями → ИИ-ассистент на каждом сайте →
заработок за покупки и задания), кнопки «Далее» / «Пропустить» / «Начать шопинг».

**H. Авторизация и аккаунты — ✅ (вывод ⬜).** Вход по email magic-link (через `DeepLinkRouter`)
и Apple Sign In; привязка аккаунтов МП (вход на сайтах) как задание +100 ₽; профиль, экран
истории операций с фильтрами; выпуск карты Газпромбанка для вывода.

**I. Контекстные подсказки — ✅.** Кешбэк-тултип (1 раз/сессия при заходе на МП, анонс +200 ₽ за
первую покупку, автозакрытие 15 сек); хинт «Анализировать» (1 раз за всё время, через 0.8 сек
после загрузки товара Ozon, указывает на ✦).

**J. Аналитика (AppMetrica) — ✅.** 25+ событий (страницы, навигация, чат, анализ, сравнение,
кошелёк, колесо, вывод); e-commerce события (просмотр товара Ozon); профиль пользователя (тип
приложения, версия, счётчик запусков, статус пушей); push-уведомления через AppMetrica Push SDK.

**K. Наблюдаемость и трейсинг (backend) — ✅.**
- `browser.agent_trace` (ClickHouse) — полная запись хода: системный промпт, запрос/ответ LLM по
  итерациям, все тул-коллы и результаты, под-шаги тулов (markdown.new / webview / yandex /
  clickhouse), финальный ответ. Группировка `run_id` → `chat_id` → `device_id`; гейт `AGENT_TRACE_ENABLED`.
- `browser.agent_dialog_report` — ручные репорты диалогов (категория + комментарий), дубль в Sentry.
- `browser.llm_log` — сводка вызовов LLM (функция, модель, латентность).

> **Ядро-носитель** — модуль A (браузер): всё остальное (ассистент, анализ, сравнение, кешбэк)
> работает только внутри него. **Самые зрелые** модули — ассистент (E) и анализ Ozon (C); **наименее
> зрелый** — кешбэк-программа (F) из-за отсутствия backend.

## 4. Пользовательские сценарии (флоу, механически)
1. **Анализ товара Ozon:** открыл карточку → детект product ID → инъекция `ozon-collector.js` →
   `/ingest` → SSE-отчёт с прогрессом → итоговая оценка 0–10 и списки плюсов/минусов.
2. **Кросс-МП сравнение:** запрос → скрытые WKWebView WB+ЯМ → параллельный поиск (таймаут 18 сек,
   fallback DOM) → `/compare` (ИИ-саммари + матчинг топ-10) → карточки товаров.
3. **Диалог с ассистентом:** тап ✦ → автопроброс контекста страницы → агентный цикл (до 6
   итераций, тул-юз) → SSE токены/статусы инструментов → ответ с чипами-источниками.
4. **Начисление кешбэка:** покупка на сайте, открытом в КБ → «Проверяем» → подтверждение →
   баланс (mock) → прогресс к порогу → вывод от 600 ₽ (backend в разработке).
5. **Геймификация:** ежедневный вход (стрик) / выполнение заданий / колесо удачи → пополнение баланса.
6. **Поделиться в КБ:** системный share sheet → `cashbackbrowser://open` → новая вкладка / Яндекс-поиск.

## 5. Технические требования и ключевые ограничения
- **Главное требование кешбэк-механики:** надёжно фиксировать факт покупки на произвольном сайте,
  открытом в браузере. Сейчас backend этой фиксации **не реализован** (UI работает на mock).
- **Жёсткая граница:** всё вне браузера КБ (нативные приложения МП, СБП/банк-приложение) — вне
  отслеживания. Это граница продукта, не баг.
- **JS-коллекторы** (Ozon/WB/ЯМ) зависят от вёрстки и API площадок — хрупки к их изменениям;
  есть fallback на DOM-скрапинг и таймауты (18 сек на сравнение).
- **Зависимость от внешних сервисов:** OpenRouter + Cloudflare AI Gateway (LLM), Yandex Cloud
  Search API (с лимитами), markdown.new (чтение страниц) — латентность и сбои внешние.

## 6. Платформа, стек, доступ
- **iOS:** Swift, SwiftUI, WKWebView, Combine. Архитектура MVVM (`BrowserViewModel`,
  `RewardsViewModel`, `AIAssistantViewModel`).
- **Backend:** `https://api.cashbackbrowser.ru` — FastAPI, SSE-стриминг (auth — `api-test.cashbackbrowser.ru`).
- **ИИ:** Claude Sonnet 4.5 (агент с тул-юзом) + Gemini Flash (саджесты) через OpenRouter и
  Cloudflare AI Gateway. Веб-поиск — Yandex Cloud Search API (через CF AI Gateway); чтение
  публичных страниц — markdown.new.
- **JS-коллекторы:** инъекция в WKWebView для Ozon, WB, Яндекс Маркет.
- **Хранилище:** ClickHouse (товары, вердикты, трейсы диалогов, логи LLM). Клиент: локально
  `cashback.json`, `LocalChatRepository`.
- **Аналитика:** AppMetrica (события + пуш). **Ошибки:** Sentry.

## 8. Вынесено за скобки в этом цикле
В цикле **v3** (см. [[product-positioning]]) на передний план выводится только связка
**браузер-носитель + кешбэк-программа за покупки через браузер**. Модули **ИИ-ассистент (E),
анализ товаров Ozon (C), кросс-МП сравнение (D)** — реально существуют, но **за скобками** угла
(их value-исследование велось в линии `main`). Это решение позиционирования, а не удаление
функциональности: при другом угле эти модули снова выходят вперёд без изменений сборки.

## 9. Открытые технические вопросы и риски реализации
- **Детект факта покупки на произвольном сайте** — основа кешбэк-механики — как надёжный backend
  не реализован; от него зависит, что вообще можно обещать в позиционировании.
- **Backend вывода и баланса кешбэка** — в разработке (сейчас mock) → прямой риск доверия к выплатам.
- ⚠️ **Расхождение сборки и угла v3.** Фактическая механика — **% по категории + геймификация**
  (ежедневный бонус, задания, колесо, карта-партнёр). Идеализированная механика v3-описания —
  **фикс ~10 ₽ за любую покупку + лимит «один мерч/день»**. Эти модели **не совпадают** — downstream
  обязан сверять, какую из них проверяет (флаг для [[product-positioning]] и [[product-description]]).
- **Хрупкость JS-коллекторов** к изменениям вёрстки/API МП; анализ ограничен Ozon.
- **Зависимость от внешних API** (LLM-шлюзы, Yandex Search, markdown.new) — лимиты, латентность, сбои.
- **Вкладки не персистятся**; продукт **не опубликован** в App Store.
