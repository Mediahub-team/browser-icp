# Промт для AI-генерации лендинга — O11/O12, ICP-05 + ICP-06 (мотив C, доверие к выплате)

> Готовый промт для генерации дизайна/кода (главный таргет — **Claude / Artifacts**; ядро
> универсально). Контент взят из [[landings/icp05-06]], [[offer-c-trust-gated]],
> [[product-description]], customer language ICP-05/06.
>
> 🎓 **ОБУЧАЮЩАЯ ЯЧЕЙКА.** Ключ страницы — **усиленный intent-блок** (чекбокс «готов первым»),
> на нём считаем дисконт ложных заявок и разрыв signup ↔ интент.

## Как пользоваться
1. Скопируй блок ПРОМТ целиком. 2. Вставь в Claude (или иной сервис). 3. Получишь
адаптивный лендинг одним файлом. 4. Проверь по чек-листу внизу.

---

## ПРОМТ (копировать целиком)

```
Ты — продуктовый веб-дизайнер и фронтендер. Сделай ОДНОСТРАНИЧНЫЙ адаптивный лендинг
(mobile-first) одним самодостаточным файлом: HTML + Tailwind (CDN) + минимум JS.
Никаких внешних зависимостей кроме Tailwind CDN. Верни один файл, готовый открыть в браузере.

КОНТЕКСТ ПРОДУКТА (пред-запуск, продукт ещё не вышел):
iOS-браузер с ИИ-ассистентом и проверкой товара на маркетплейсах, который возвращает кешбэк
рублями с выводом на карту. На этой странице ведущая ценность — КЕШБЭК, КОТОРЫЙ РЕАЛЬНО ВЫВОДИТСЯ
(доверие к выплате), а не размер процента.
ЧЕСТНОСТЬ (обязательно соблюдать, не приукрашивать): бэкенд вывода ещё в разработке — НЕ обещать
конкретные процент/порог/срок («honor-at-launch»); глубокая проверка товара пока только на Ozon.

ЦЕЛЬ СТРАНИЦЫ: единственное целевое действие — оставить заявку в ЛИСТ ОЖИДАНИЯ (e-mail).
Продукт ещё не запущен — не предлагай «скачать приложение».

АУДИТОРИЯ И ТОН: ICP-05 «Охотники за выгодой» (уже на Letyshops, обожглись на «обещали — не
выплатили») + ICP-06 heavy-buyers Ozon/WB (кешбэк набегает, но проходит мимо). Мотив C — доверие
к выплате; для heavy-сегмента добавь S-крючок «проверь детское/товар до заказа». Тон — спокойный,
честный, «банковский» (доверие, не скидочный хайп); эмоция в заголовках допустима, давление — нет.
ЯЗЫК (вставь дословно в тексты): «обещали процент, а он не упал», «дайте вывести маленькую сумму
быстро — тогда поверю», «аннулировали без причины», «дарю площадке от лени», «набегает прилично».
СЛОВА-ТАБУ (не употреблять): любые конкретные цифры процента/порога/срока вывода и связывающие
обещания выплат; «успей/осталось N мест/таймер»; «нейро/LLM/агент/тул»; «революция шопинга»;
не обесценивать приложения Ozon/WB в лоб.

СТРУКТУРА (сверху вниз):
1. Hero: H1 = «Кешбэк, который реально выводится — честно, без холда»; подзаголовок = «Без "после
   проверки", без аннулирований "без причины". В этот раз кешбэк ты выведешь сам — и поверишь,
   потому что проверишь» (без процента/порога/срока); кнопка CTA «Записаться в лист ожидания».
   Рядом — схематичные статусы «Проверяем → Начислено → Выведено ✓» (без сумм).
2. Три буллета ценности:
   - «Обещали процент, а он не упал» — больше нет: прозрачные статусы начисления, без тихих аннулирований;
   - «Дайте вывести маленькую сумму быстро — тогда поверю»: первый вывод своими руками, без порога-заложника (без цифр);
   - Хватит дарить площадке от лени: кешбэк на твоём объёме возвращается тебе, а для частых заказов — ещё и проверка товара/продавца до покупки.
3. Demo-блок: схематично покажи цепочку статусов вывода (без сумм) И иллюстративный мини-калькулятор
   «сколько теряешь на объёме» (подпиши «иллюстративно, без обещанного процента») + плашку «проверь
   детское до заказа». Без фото-стоков, только мокап/иллюстрация.
4. Блок доверия: как устроен вывод (статусы, без тихих аннулирований), честная граница «глубокая
   проверка товара пока на Ozon», независимость. Обязательный honor-at-launch дисклеймер мелким, но
   заметным: «Продукт в разработке. Точные условия вывода (процент, порог, сроки) объявим на запуске —
   здесь мы их не фиксируем».
5. Форма waitlist: поле e-mail + кнопка. ПОСЛЕ отправки показать УСИЛЕННЫЙ intent-блок (ключ теста):
   - вопрос «Что для вас главное?» с вариантами: «вывести кешбэк без холда», «проверить товар до
     покупки», «сколько теряю на объёме», «просто посмотреть» (контрольный);
   - чекбокс «Готов попробовать первым и оставить отзыв» — это ГЛАВНЫЙ сигнал интента, сделай его
     заметным; заявки без галочки потом взвешиваются ниже.
   (JS: по сабмиту прятать форму, показывать intent-блок и «спасибо»; данные никуда не шлём — заглушка,
   но сохрани состояние чекбокса и выбранный вариант в data-атрибутах/console для замера.)
6. Лёгкое соц.доказательство (плейсхолдеры цитат про реальные выплаты + счётчик ожидающих) + короткий футер.

ДИЗАЙН: mobile-first, чистая типографика, спокойная «банковская» палитра доверия (тёмно-синий + зелёный
акцент на «Выведено ✓»), без распродажного красного. Без таймеров, без «осталось N мест», без давления.
Доступность (контраст, размеры тапа). Семантический HTML.

ИЗМЕРЕНИЕ (заглушки, без реальных ключей): предусмотри место под цель Метрики «waitlist_signup»
(data-атрибут на форме), фиксацию чекбокса «готов первым» и ответа микро-вопроса, и чтение UTM из URL.

Верни ТОЛЬКО код одного файла.
```

## Чек-лист после генерации
- [ ] CTA = «лист ожидания», нет «скачать приложение».
- [ ] Нет слов-табу и НИ ОДНОЙ связывающей цифры (%/порог/срок); использован customer language.
- [ ] Есть **усиленный** intent-блок после заявки (микро-вопрос + чекбокс «готов первым»).
- [ ] Соблюдены честность-констрейнты (honor-at-launch дисклеймер, проверка товара Ozon-only).
- [ ] Mobile-first, адаптивно, спокойный тон, без давления/таймеров.
