# Промт для AI-генерации лендинга — ICP-01 AI-power-users (мотив A, «без копипаста»)

> Готовый промт для генерации лендинга. **Главный таргет — Claude (Artifacts)**; ядро
> универсальное. Это пред-продуктовый waitlist-лендинг (дешёвый kill-fast эксперимент):
> только механика «без копипаста», без «умного ассистента» и без кешбэка/шопинга.
> Источники: [[landings/icp01]], [[offer-icp01-power]], [[icp-01-ai-power-users]],
> [[product-description]].

## Как пользоваться
1. Вставь блок ПРОМТ целиком в Claude (или иной сервис). 2. Получишь адаптивный лендинг
одним файлом. 3. Проверь по чек-листу внизу.

---

## ПРОМТ (копировать целиком)

```
Ты — продуктовый веб-дизайнер и фронтендер. Сделай ОДНОСТРАНИЧНЫЙ адаптивный лендинг
(mobile-first) одним самодостаточным файлом: HTML + Tailwind (CDN) + минимум JS.
Никаких внешних зависимостей кроме Tailwind CDN. Верни один файл, готовый открыть в браузере.

КОНТЕКСТ ПРОДУКТА (пред-запуск, продукт ещё не вышел):
iOS-браузер с ИИ, который видит ту страницу, что у тебя открыта (URL, заголовок, текст),
и работает по всему вебу: спрашиваешь прямо на странице, без копипаста и переключения в чат.
ЧЕСТНОСТЬ (обязательно соблюдать, не приукрашивать): браузер ещё в разработке, доступ
открываем по списку ожидания; без обещаний конкретных цифр и сроков.
ВАЖНО — ПОЗИЦИОНИРОВАНИЕ: бей ТОЛЬКО в механику (копипаст / ИИ видит открытую страницу /
мобайл / PDF / контент за логином / 4 вкладки → таблица). НЕ продавай «умный ассистент»
(у аудитории уже есть ChatGPT — в лоб проиграешь). НЕ упоминай кешбэк, скидки, шопинг,
маркетплейсы вообще нигде.

ЦЕЛЬ СТРАНИЦЫ: единственное целевое действие — оставить заявку в ЛИСТ ОЖИДАНИЯ (e-mail).
Продукт ещё не запущен — не предлагай «скачать приложение».

АУДИТОРИЯ И ТОН: ICP-01 AI-power-users (ранние адопторы ИИ: продакты, IT, аналитики,
ресёрчеры; живут в ChatGPT/Claude ежедневно). Мотив A — контроль/эффективность. Тон —
простой, по делу, «механика, а не интеллект», как пишут гики друг другу; без пафоса.
ЯЗЫК (вставь дословно в тексты): «достало копипастить в чат»; «а можешь прямо по этой
странице?»; «он что, видит что у меня открыто?»; «курьер между вкладкой и чатом».
СЛОВА-ТАБУ (не употреблять): умный ассистент/помощник, нейросеть нового поколения,
революционный, кешбэк, скидки, шопинг, маркетплейс, LLM, агент, тул, казёнщина.

СТРУКТУРА (сверху вниз):
1. Hero: H1 = «Хватит быть курьером между вкладкой и чатом»; подзаголовок = «ИИ работает
   с открытой страницей и вебом — спрашиваешь прямо на ней. Без копипаста и переключения
   вкладок»; кнопка CTA «Записаться в лист ожидания».
2. Три буллета ценности:
   - «Не копируешь — ИИ видит страницу.» Открыл → спросил → ответ по тому, что на экране;
   - «Работает там, где копировать нельзя: мобайл, PDF, контент за логином»;
   - «4 вкладки → одна таблица „суть / риск / что делать“» — без ручной сводки.
3. Demo-блок (две схематичные иллюстрации/мокапа, без фото-стоков):
   - Демо 1 (O9) «не копируешь — ИИ видит страницу»: before (выделить → переключиться в чат
     → вставить → ждать) / after (открыл страницу → спросил → ответ по ней). Подпись:
     «ИИ читает ту самую страницу, что открыта — даже PDF / за логином»;
   - Демо 2 (O10) «мульти-таб синтез»: 4 открытые вкладки → один тап → таблица
     «суть / риск / что делать» со ссылками; колонка «риск» подсвечивает расхождения. Подпись:
     «4 ссылки → сводная таблица, без копипаста между вкладками».
4. Блок честности: «Браузер пока в разработке, открываем доступ по списку. Без обещаний
   цифр и сроков.» (Кешбэк/шопинг НЕ упоминать.)
5. Форма waitlist: поле e-mail + кнопка. ПОСЛЕ отправки показать intent-блок:
   - вопрос «Что для вас главное?» с вариантами: «спросить прямо на странице»,
     «страницы за логином и PDF», «свести несколько вкладок в таблицу», «просто интересно»
     (контрольный вариант низкого интента; вариант «кешбэк» НЕ добавлять);
   - чекбокс «Готов попробовать первым и оставить отзыв».
   (JS: по сабмиту прятать форму, показывать intent-блок и «спасибо»; данные никуда не
   шлём — заглушка.)
6. Лёгкое соц.доказательство (плейсхолдеры цитат «таких же гиков» + счётчик ожидающих) +
   короткий футер.

ДИЗАЙН: mobile-first, чистая типографика, инструментальный минимализм (светлая база, один
акцентный цвет, уместны моноширинные акценты), как продуктивити-тула для гиков. Без
таймеров, без «осталось N мест», без давления. Доступность (контраст, размеры тапа).
Семантический HTML. Без стоковых лиц.

ИЗМЕРЕНИЕ (заглушки, без реальных ключей): предусмотри место под цель Метрики
«waitlist_signup» (data-атрибут на форме) и чтение UTM из URL
(utm_source/medium/campaign/content).

Верни ТОЛЬКО код одного файла.
```

## Чек-лист после генерации
- [ ] CTA = «лист ожидания», нет «скачать приложение».
- [ ] Нет слов-табу; не назван «умным ассистентом»; нет кешбэка/шопинга/маркетплейсов.
- [ ] Использован customer language (копипаст / курьер между вкладкой и чатом / видит страницу).
- [ ] Оба демо на месте (O9 «ИИ видит страницу» + O10 «4 вкладки → таблица»).
- [ ] Есть intent-блок после заявки (микро-вопрос с «просто интересно» + чекбокс), без «кешбэк»-варианта.
- [ ] Mobile-first, адаптивно, без давления/таймеров.
