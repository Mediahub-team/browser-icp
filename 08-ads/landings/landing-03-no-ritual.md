# ТЗ для дизайнера — лендинг offer-03-no-ritual × ICP-02 optimizers

> ТЗ на **пред-продуктовый лендинг** связки **T4**. Цель — **заявка в лист ожидания** + intent-сигнал.
> **Калибровка ([[comparison-2026-06-15]] §6):** ось страницы = **РИТУАЛ** («ловит сам, без захода по
> ссылке») + **дельта против стека**. **НЕ строить на «живые рубли вместо баллов»** — у оптимизаторов
> кешбэк не заперт (агрегаторы выводят), эта ось у них не работает.
>
> ⚠️ **Честность (K3).** «5–15% на МП» — только с меткой «условия пилота»; дельта в рублях — **прикидка
> на покупках пользователя**, не гарантия. Пруф вывода обязателен (сегмент обжёгся: «обещали 7%, дали
> 1,2%»). Ничего против инвариантов [[product-functionality]] §2.
>
> 🛠 Все формулировки — через `russian-copywriting` (живой «ты», без канцелярита, ФЗ-38).
> 🚫 Анти-проброс этапов 0–7: факты и голоса клиента — сырьё, тексты написаны заново.
> ✅ **Message match:** H1 = фраза-обещание [[creative-03-no-ritual]] §1 **дословно**.

---

## 1. Контекст и цель
- **Продукт (1 фраза):** iOS-браузер, возвращающий кешбэк за покупки через него — за любой сайт + 5–15% на маркетплейсах (условия пилота), **ловит сам, без партнёрской ссылки**.
- **Стадия:** пред-запуск. **Единственная цель:** заявка в лист ожидания (e-mail).
- **Сегмент / угол:** ICP-02 — контроль/самоутверждение («выжимаю максимум, но устал жонглировать»); **боль:** ритуал — «половину кешбэка теряю, забываю зайти по ссылке».
- **Откуда трафик:** Telegram (посевы + Ads, ядро) / VK / Яндекс Директ → UTM.
- **Главный KPI:** **CPS** + распределение intent-ответов (§11), особенно «готов перенести покупки».

## 2. Аудитория и тон
- **Кто:** расчётливый оптимизатор со стеком «агрегатор + категории банка + промокоды»; верит цифрам и скринам, не лозунгам; уже менял канал ради выгоды; обжёгся на агрегаторах. «Изменение, которое покупает» — снять ручной ритуал, не теряя контроля.
- **Tone of voice:** спокойный, расчётный, «инженерный», на равных. Язык расчёта, не ажиотажа.
- **Customer language (вставить ДОСЛОВНО):** «у меня уже связка — чем ты лучше», «надоело заходить через ссылку каждый раз», «пруф вывода покажи», «посчитаем, сколько реально выходит», «обещали 7%, дали 1,2%».
- **Слова-табу:** «халява», «лёгкие деньги», «просто скачай», «живые рубли вместо баллов», «гарантируем».

## 3. Описание и нарратив
- **Главный вывод (one takeaway):** «Мой ручной ритуал заходить по ссылке больше не нужен — браузер ловит кешбэк сам, и я вижу, что это даёт **сверх** моего стека, с пруфом вывода».
- **Логика убеждения:** ритуал-боль (узнавание) → обещание «ловит сам» → сравнение со **стеком** + дельта в рублях → пруф вывода (снять K3) → лёгкое действие (waitlist).
- **Уровень осознанности:** problem-aware остро (боль ритуала осознана) → можно быстро к механике и сравнению; проблематизация короткая.

## 4. Структура секций (сверху вниз)
1. **Hero.** H1 = фраза-обещание креатива **дословно** (см. §5) + подзаголовок + CTA + честный демо-визуал. **В первых двух экранах — конкретный сценарий «забыл зайти по ссылке → потерял»** (см. §5, блок-сценарий).
2. **Ценность — 3 буллета** языком клиента: «ловит сам, без захода по ссылке» / «весь стек в одном месте» / «дельту считаешь на своих покупках». Сценарная математика — цифры покупок клиента ОК; «5–15%» только с меткой «условия пилота».
3. **Demo / «как это работает».** 2–3 шага: «открыл магазин в браузере → купил как обычно → возврат начислен сам». **Барьер смены канала назвать прямо:** да, покупать надо через этот браузер, а не через приложение/агрегатор — и именно поэтому нечего забывать (ритуал исчезает). Не замазывать.
4. **Возражения (ключевая секция).**
   - **№1 (обязательный, из оффера) — «у меня уже стек — ты вместо или ещё одна вкладка?»** → **таблица-сравнение со стеком**: что **остаётся** (твои карты, крупные категории), что **добавляется** (авто-ловля без ссылок, покрытие сайтов без партнёра), **дельта в рублях** (прикидка на корзине пользователя, см. сценарий) + честно «можно держать параллельно и сравнить по факту». Здесь же — **пруф вывода** (они обжигались): скрин статуса «проверка → подтверждено → на карте», пометка «образец».
   - «А выплатят? пруф вывода покажи» → блок доверия §5 (механика источника денег + статус + оферта).
   - «Опять обещаете 7%, дадите 1,2%?» → честная оговорка «5–15% — условия пилота», дельту считаем на твоих покупках, не обещаем абстракцию.
5. **Доверие / честность.** На чём держится возврат (партнёрская комиссия магазина — нам выгодно, чтобы покупка состоялась); честная граница «что пока не делаем» (покупки внутри приложений МП, офлайн); анти-K3 визуал.
6. **Форма waitlist.** Лестница §6.
7. **Соц.доказательство — блок «от основателя»** (кто и зачем делает, build-in-public). Без выдуманных цитат и счётчиков.
8. **Футер.** Короткий; оферта/политика; пометка рекламы если нужно.

## 5. Копирайтинг (точные тексты)
- **H1 (hero) — ДОСЛОВНО из креатива:** «**Кешбэк-браузер ловит сам — даже когда забыл зайти по ссылке**».
- **Подзаголовок:** «Кешбэк за любой сайт и 5–15% на маркетплейсах (условия пилота). Без захода через агрегатор — браузер ловит возврат сам».
- **Блок-сценарий (в первых двух экранах):** «Корзина на 20 000 ₽ в месяц. Стек по факту дал ~500 ₽ — половину съели забытые ссылки и неначисления. Браузер ловит сам: 5–15% на МП по условиям пилота. **Дельту посчитаем на твоих покупках.**» *(цифры покупок — клиента; % — с меткой пилота; дельта — прикидка, не гарантия).*
- **CTA-копи (кнопка):** «Записаться в лист ожидания» *(повтор после demo и после сравнения).*
- **3 буллета ценности:** «Ловит кешбэк сам — заходить по ссылке не надо» · «Весь твой стек кешбэка — в одном браузере» · «Видишь дельту в рублях против того, что выходит сейчас».
- **Заголовок demo-блока:** «Как это работает»; шаги: «1. Открой магазин в браузере» · «2. Купи как обычно» · «3. Возврат начислен сам — без ссылок».
- **Заголовок блока сравнения:** «У тебя уже есть связка? Сравни, что меняется».
- **Блок доверия — заголовок + фраза:** «Покажем, как возврат доходит до карты» · «Статус каждого начисления виден по шагам; возврат держится на комиссии магазина — нам выгодно, чтобы покупка состоялась».
- **Лейбл поля формы:** «Твой e-mail».
- **Микрокопи под формой:** «Не спамим. Напишем, когда откроем доступ».
- **Состояние «спасибо»:** «Ты в списке. Спасибо!».
- **Текст ошибки:** «Проверь e-mail».

## 5.1 Картинки (скилл `image`, честные мокапы)
- **Hero:** A — спокойный экран браузера на привычном магазине, бейдж «возврат начислен» без суммы; B — «до/после»: ворох вкладок кешбэк-сервисов → один спокойный экран. Без сумм/процентов на картинке.
- **Demo:** три кадра-схемы «открыл → купил → возврат сам», иконки в бренд-цвете; либо реальный скрин прототипа с подсвеченным шагом (не AI-интерфейс).
- **Доверие/K3:** экран статуса «проверка → подтверждено → на карте», нейтральные подписи, пометка «образец». Без золотых монет, печатей «100%», чужих скринов выплат.
- **Избегать:** стоковые улыбки, дождь из денег, фиолетовые градиенты-клише, выдуманные суммы, AI-генерация интерфейса.

## 6. Обязательные элементы конверсии
- **CTA** минимум дважды (hero + после demo/сравнения), визуально приоритетна.
- **Лестница действия:** шаг 1 — e-mail; шаг 2 — платформа «iPhone / Android» (продукт iOS — квалификация + intent-сигнал); шаг 3 — intent-блок §11; опц. — подписка на TG-бота (для трафика из TG). **Мерим глубину прохождения**, не только факт заявки.
- Без давления/таймеров/«осталось N мест».

## 7. Визуальная иерархия и стиль
- Приоритет: H1 → CTA → сценарий/сравнение → demo → доверие. Один акцентный цвет на CTA.
- Палитра «спокойно/надёжно/расчётно»; типографика читаемая, табличный блок сравнения — аккуратный.
- Imagery: честные мокапы, WebP+фолбэк, hero/OG 1200×630 <200 КБ, width/height заданы (CLS), lazy ниже экрана, alt у всех.

## 8. Адаптив и состояния
- Mobile-first; брейкпоинты 360–430 / 768 / 1200+.
- Форма: default · focus · loading · success (intent-блок) · error. CTA: default · hover/active · disabled.

## 9. Доступность
- Контраст ≥ WCAG AA; tap-target ≥44×44; видимый focus; alt; семантический HTML; клавиатурная навигация.

## 10. Технические требования
- Адаптив, быстрая загрузка. Форма → цель Метрики «waitlist_signup» (CPS); прокидывать UTM. Без сторонних трекеров кроме Метрики.

## 11. Intent-сигнал
- После заявки: «**Что для тебя главное?**» — варианты: «Чтобы ловил сам, без захода по ссылке» (под оффер) · «Чтобы выходило больше моего текущего стека» (дельта/K2) · «Чтобы точно выплатили» (контрольный/K3). Чекбокс «Готов(а) попробовать первым(ой) и оставить отзыв».
- **Доп. intent (риск K2):** «Готов(а) перенести сюда часть покупок со своего стека?» — да/нет (ключевой сигнал «вместо vs в стеке»).
- **Критерий успеха:** CPS ≤ порог (test-plan); распределение intent — какой угол резонирует (вход в этап 9).

## 12. Что НЕ делать
- Не обещать цифр выплат вне «условий пилота»; дельту не подавать как гарантию. Ничего против инвариантов.
- **Не строить страницу на «живые рубли вместо баллов»** — у ICP-02 не заперто; ось = ритуал + дельта против стека.
- Не использовать слова-табу. Целью не делать установку (продукта нет). Без давления/таймеров.

- [x] **Message match:** H1 «Кешбэк-браузер ловит сам — даже когда забыл зайти по ссылке» = фраза-обещание [[creative-03-no-ritual]] §1 дословно.
- [x] **Конкретный сценарий покупки** есть в первых двух экранах (блок-сценарий «забыл зайти по ссылке → потерял», корзина 20 000 ₽, §5).
- [x] **Возражение №1** («у меня уже стек — вместо или ещё вкладка?») имеет адресующий блок §4: таблица-сравнение (остаётся/добавляется/дельта) + пруф вывода.

## 13. Референсы и deliverables
- Референсы: спокойные финтех/расчётные лендинги, табличные сравнения «было/стало».
- Deliverables: макет (mobile + desktop), исходник, спецификация состояний формы, экспорт ассетов, спека брейкпоинтов.
