# ТЗ для дизайнера — лендинг offer-03-no-ritual / ICP-03

**Источники:** [[offer-03-no-ritual]] · [[icp-03-cashback-optimizers]] · [[product-description]] · [[comparison-2026-06-10]].

> Пред-продуктовый лендинг (waitlist). Честность (K3): без связывающих цифр кешбэка (%/сумма/срок), ничего против инвариантов [[product-functionality]] §2. Заполнено под первичный угол ICP-03.
>
> 🛠 Тексты (§3, §5) сгенерированы скиллом `russian-copywriting` («ты», по ФЗ-38, через гейт).
> 🚫 Фразы оффера/креатива не переброшены: «ловит сам», «без ритуала», «покупай как обычно», «стек поверх
> банка», «живые рубли» заменены свежими. Голоса клиента — в кавычках как сырьё.

## 1. Контекст и цель
- **Продукт (1 фраза):** iOS-браузер, который возвращает рубли за покупки, прошедшие через него.
- **Стадия:** пред-запуск. **Единственная цель:** заявка в лист ожидания (e-mail).
- **Сегмент / угол:** ICP-03 кешбэк-оптимизаторы — мотив контроль/«выжимаю максимум»; **боль:** сверять выгоду перед каждой покупкой.
- **Откуда трафик:** Telegram (кешбэк-каналы) + Яндекс Директ РСЯ → UTM кампании.
- **Главный KPI:** **CPS** (стоимость заявки) + распределение intent-ответов (§11).

## 2. Аудитория и тон
- **Кто и контекст:** считает ставки, комбинирует агрегатор+категорию+промокод; «изменение, которое покупает» — не сверять каждый раз.
- **Tone of voice:** по делу, без воды; уважительно к «прошарённости» (не объясняет, что такое кешбэк). Спокойно, не «халява». Обращение **«ты»**.
- **Customer language (как сырьё, в кавычках):** «надоело заходить через ссылку», «дайте пруф вывода», «без танцев с бубном».
- **Слова-табу:** «халява», «заработок», «лёгкие деньги», гарантии мгновенного вывода, «лучший/№1».

## 3. Описание и нарратив страницы
- **Главный вывод (one takeaway):** «Можно не сверять перед каждой покупкой, где выгоднее — рубли возвращаются сами, с любого магазина, и видно, где они».
- **Логика убеждения:** усталость от сверки → факт «возвращается отовсюду, поверх банка» → почему верить (виден статус, выплата по оферте, честно про пред-запуск) → лёгкое действие (waitlist).

## 4. Структура секций (сверху вниз)
1. **Hero.** H1 + подзаголовок + CTA «Записаться в лист ожидания» + честный мокап браузера с бейджем кешбэка.
2. **Ценность — 3 буллета:** возвращается отовсюду / складывается с банком / видно каждый рубль.
3. **Demo «как это работает».** 3 шага: ставишь и заходишь как привык → браузер сам замечает оплату → рубли копятся, статус виден.
4. **Доверие / честность.** Виден путь начисления; выплата по оферте; честная граница «покрытие нейтральных сайтов растёт — покажем, где уже работает»; «на старте — лист ожидания, не обещания».
5. **Форма waitlist.** E-mail + кнопка → intent-блок (§11).
6. **Соц.доказательство.** Плейсхолдеры цитат оптимизаторов + счётчик ожидающих (без выдуманных выплат).
7. **Футер.** Короткий; оферта/политика.

## 5. Копирайтинг (свежие формулировки, скилл `russian-copywriting`)
- **H1 (≤~60), 2 варианта:** «Перестань выгадывать, где сегодня выгоднее» · «Кешбэк со всех покупок, а не только у партнёров».
- **Подзаголовок (≤~120):** «Браузер сам замечает оплату и возвращает рубли — на любом магазине, поверх того, что уже даёт банк. Сверяться со списком не нужно.»
- **CTA-копи:** «Записаться в лист ожидания» *(повтор после demo)*.
- **3 буллета:** «Возвращается отовсюду — не из короткого списка партнёров» · «Складывается с банком, а не вместо него» · «Видно каждый рубль: на каком шаге и когда придёт».
- **Заголовок demo:** «Как это работает»; шаги: «1. Ставишь браузер и заходишь за покупками, как привык» · «2. Браузер сам замечает оплату — особых ссылок не надо» · «3. Рубли копятся на балансе, статус виден».
- **Блок доверия:** «Мы ещё не запустились и говорим прямо: зовём в лист ожидания, а не рисуем чужие скриншоты. Когда откроем — проверишь на своей первой покупке, выплата по публичной оферте.»
- **Лейбл/плейсхолдер формы:** «Твой e-mail».
- **Микрокопи под формой:** «Напишем один раз — когда откроем доступ. Без рассылок.»
- **Спасибо:** «Готово, ты в списке. Дадим знать, когда можно заходить.»
- **Ошибка формы:** «Кажется, в адресе опечатка — проверь.»

## 6. Обязательные элементы конверсии
- CTA дважды (hero + после demo), визуально приоритетна. Форма — только e-mail. Intent-блок после заявки (§11). Без давления/таймеров.

## 7. Визуальная иерархия и стиль
- Приоритет: H1 → CTA → demo → доверие. Акцентный цвет — на CTA.
- Палитра/настроение: бренд-токены (индиго-синий + зелёный акцент, светлый фон, Golos Text — `08-ads/tools/landing/design-system.css`); «стало проще».
- Imagery: честные мокапы браузера; без фото-стоков и фейк-скринов.

## 8. Адаптив и состояния
- Mobile-first; брейкпоинты 360–430 / 768 / 1200+. Состояния формы: default/focus/loading/success/error. CTA: default/hover/disabled.

## 9. Доступность
- Контраст ≥ WCAG AA; tap-target ≥ 44×44; видимый focus; alt; семантический HTML; клавиатурная навигация.

## 10. Технические требования
- Адаптив, быстрая загрузка. Форма → цель Метрики «waitlist_signup»; UTM из URL. Без сторонних трекеров.

## 11. Intent-сигнал и измерение
- После заявки: «Что для тебя здесь главное?» — варианты: «Чтобы возвращалось со всех магазинов, а не из списка» / «Чтобы выплату было видно и не зажали» / «Чтобы давало больше, чем мой банк» *(контроль ставки)*; чекбокс «Готов(а) попробовать первым(ой) и сказать, что не так».
- **Критерий успеха:** CPS ≤ порога [[test-plan]]; распределение intent (покрытие / доверие / ставка) — вход для этапа 9.

## 12. Что НЕ делать
- Не обещать % / сумм / сроков кешбэка; ничего против инвариантов. Без слов-табу и «лучший/№1». Цель — не установка приложения (его ещё нет). Без давления/таймеров.

## 13. Референсы и deliverables
- **Референсы:** «эталон на бренде» — `08-ads/tools/landing/` (генератор + design-system.css).
- **Deliverables:** макет (mobile + desktop), исходник, спецификация состояний формы, экспорт ассетов, спека брейкпоинтов.
