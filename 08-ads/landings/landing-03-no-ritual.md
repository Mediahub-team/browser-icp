# ТЗ для дизайнера — лендинг offer-03-no-ritual / ICP-03

**Источники:** [[offer-03-no-ritual]] · [[icp-03-cashback-optimizers]] · [[product-description]] · [[comparison-2026-06-10]].

> Пред-продуктовый лендинг (waitlist). Единственная цель — заявка в лист ожидания + снятие intent-сигнала. Угол первичного сегмента — **возврат считается сам, без ритуала переключения сервисов**.
> ⚠️ **Честность (K3):** без связывающих цифр кешбэка (процент / сумма / срок), ничего против инвариантов [[product-functionality]] §2 (возврат — только за покупки через браузер). Иллюстрации показывают продукт честно.
> 🛠 Все формулировки — через `russian-copywriting` (живой русский, обращение «ты», без канцелярита, ФЗ-38). Картинки — через `image` (§5.1).
> 🚫 Формулировки оффера / креатива не пробрасываем. Слоганы «ловит сам, без ритуала», «один браузер вместо пяти сервисов» **не используем** — пишем заново; голоса клиента — в кавычках как сырьё.

---

## 1. Контекст и цель
- **Продукт (1 фраза):** iOS-браузер, который возвращает живые рубли за покупки, прошедшие через него.
- **Стадия:** пред-запуск. **Единственная цель страницы:** заявка в лист ожидания (e-mail).
- **Сегмент / угол:** ICP-03 кешбэк-оптимизаторы — мотив контроль/«выжимаю максимум»; **боль:** ритуал — заходить через ссылку, проверять категорию, помнить промокод перед каждой покупкой.
- **Откуда трафик:** Telegram (кешбэк-каналы) + Яндекс Директ РСЯ → метка кампании в **UTM**.
- **Главный KPI:** **CPS** (стоимость заявки) + распределение intent-ответов (§11).

## 2. Аудитория и тон
- **Кто и контекст:** считает ставки, держит связку «агрегатор + категория банка + промокод», устал от ритуала перед каждой покупкой; разбирается в теме — не надо объяснять, что такое кешбэк. «Изменение, которое покупают» — один инструмент вместо зоопарка.
- **Tone of voice:** по делу, с конкретикой, на равных; обращение **«ты»** (аудитория из TG/VK, разбирается в кешбэке). Без ажиотажа и «халявы» — сегмент скептичен к рекламе, верит расчёту и пруфу.
- **Customer language (как сырьё, в кавычках):** «надоело заходить через ссылку каждый раз», «у меня уже связка — чем ты лучше», «пруф вывода покажи».
- **Слова-табу:** «халява», «заработок», «лёгкие деньги»; «лучший / №1 / гарантированно / 100 %»; точные суммы / проценты / сроки.

## 3. Описание и нарратив страницы
- **Главный вывод (one takeaway):** «Можно перестать прогонять каждую покупку через сервисы — браузер замечает оплату сам, на любом сайте, и складывает возврат поверх банка.»
- **Логика убеждения:** ритуал отнимает время и всё равно половина покупок мимо (боль) → браузер считает возврат сам, без ссылок, за любой сайт (обещание) → почему верить: виден статус начисления, выплата по оферте, честно про пред-запуск (RTB) → лёгкое действие (waitlist).

## 4. Структура секций (сверху вниз) — что в каждой
1. **Hero.** H1 (главный посыл) + подзаголовок (механика простыми словами) + **CTA** «Записаться в лист ожидания» + честный мокап браузера с бейджем возврата на обычной покупке (концепты — §5.1).
2. **Ценность — 3 буллета.** Не надо открывать сервис и искать ссылку / считается за любой сайт, не только у партнёров / складывается поверх банковского кешбэка.
3. **Demo / «как это работает».** 3 шага: покупаешь через браузер как обычно → браузер сам замечает оплату → возврат рублями на балансе, статус видно (визуал — §5.1).
4. **Доверие / честность.** Виден путь начисления; выплата по публичной оферте; честная граница «считается за покупки через браузер; детект на нейтральных сайтах ещё расширяем — покажем, где уже работает»; анти-возражение «а выплатят ли» (визуал — §5.1).
5. **Форма waitlist.** E-mail + кнопка; **после отправки** — intent-блок (§11).
6. **Соц.доказательство.** Плейсхолдеры цитат оптимизаторов + счётчик ожидающих (заменить на реальные, без выдуманных выплат).
7. **Футер.** Короткий, без отвлекающих ссылок; оферта / политика.

## 5. Копирайтинг (свежие формулировки, скилл `russian-copywriting`)
- **H1 (≤ ~60 симв.), 2 варианта:** «Возврат считается сам, пока ты покупаешь» · «Покупки на любом сайте — возврат без отдельных сервисов».
- **Подзаголовок (≤ ~120 симв.):** «Покупаешь на сайтах как привык — браузер замечает оплату и считает возврат. Заходить через ссылки и проверять категории не нужно.»
- **CTA-копи (кнопка):** «Записаться в лист ожидания» *(повтор после demo)*.
- **3 буллета ценности:** «Не открываешь сервис и не ищешь ссылку перед покупкой» · «Считается за любой сайт, не только у партнёров» · «Складывается поверх банковского кешбэка».
- **Заголовок demo-блока:** «Как это работает»; подписи к шагам: «1. Покупаешь через браузер, как обычно» · «2. Браузер сам замечает оплату — ссылки не нужны» · «3. Возврат рублями на балансе, статус видно».
- **Блок доверия — заголовок + 1–2 фразы:** «Скажем честно: мы ещё не запустились — зовём в лист ожидания. Когда откроем, проверишь на своей покупке: каждый шаг начисления видно, выплата по публичной оферте.»
- **Лейбл поля формы / плейсхолдер:** «Твой e-mail».
- **Микрокопи под формой:** «Напишем один раз — когда откроем доступ. Без рассылок.»
- **Состояние «спасибо»:** «Готово, ты в списке. Дадим знать, когда можно заходить.»
- **Текст ошибки формы:** «Кажется, в адресе опечатка — проверь.»
- **Intent-вопрос и варианты:** см. §11.

## 5.1 Картинки — варианты по местам (скилл `image`)
> Картинки даём вариантами: 2–3 концепта на место, дизайнер выбирает/тестирует. Конкретных сумм и процентов на картинке не показываем. WebP + фолбэк; hero/OG 1200×630 < 200 КБ; `width`/`height` заданы (против CLS); ниже экрана `loading="lazy"`; alt у всех.

**Hero (главный визуал — «возврат сам, без ритуала»):**
- A. Спокойный экран браузера на карточке обычного магазина, скромный бейдж «возврат начислен» **без суммы**. Чисто, контраст AA, без мелкого нечитаемого текста.
- B. «До / после»: слева — несколько открытых вкладок сервисов и промокодов перед оплатой, справа — один экран браузера с бейджем возврата. Без агрессивных стрелок и капса.
- C. Телефон на странице оплаты нейтрального магазина, мягко подсвечен бейдж возврата. Нейтральный фон, без стоковых лиц.

**Demo / «как это работает» (механика, 3 шага):**
- A. Три плоских кадра-схемы «покупаешь → браузер замечает оплату → возврат на балансе», иконки в бренд-цвете, без перегруза и цифр.
- B. Один экран прототипа браузера с подсвеченным текущим шагом и тонкой полосой прогресса. Реальный скриншот прототипа, не AI-интерфейс.

**Доверие / K3 (визуал надёжности):**
- A. Экран статуса начисления (реальная механика): нейтральные подписи «проверка → подтверждено», **без сумм**; пометка «образец».
- B. Сдержанный блок со значком оферты/документа, палитра «надёжно». Без золотых монет, печатей «100 %» и галочек-гарантий.

> **Избегать везде:** стоковые улыбающиеся люди, золотые монеты и «дождь из денег», фиолетовые градиенты-клише, мелкий нечитаемый текст, выдуманные суммы/проценты и чужие скриншоты выплат, AI-генерация интерфейса (берём скриншот прототипа).

## 6. Обязательные элементы конверсии
- **CTA** дважды (hero + после demo), визуально приоритетна. Форма — только e-mail. Intent-блок после заявки (§11). Без давления/таймеров/«осталось N мест».

## 7. Визуальная иерархия и стиль
- **Приоритет внимания:** H1 → CTA → demo → доверие. Один доминирующий акцентный цвет — на CTA.
- **Палитра/настроение:** бренд-токены (индиго-синий + зелёный акцент, светлый фон, Golos Text — `08-ads/tools/landing/design-system.css`); «стало просто, без возни».
- **Imagery:** честный мокап браузера; без фото-стоков и фейк-скринов.

## 8. Адаптив и состояния компонентов
- **Mobile-first**, брейкпоинты mobile 360–430 / tablet 768 / desktop 1200+.
- **Состояния формы:** default · focus · loading · success (intent-блок) · error. **CTA:** default · hover/active · disabled.

## 9. Доступность (a11y)
- Контраст ≥ WCAG AA; tap-target ≥ 44×44; видимый focus-state; alt у изображений; семантический HTML; навигация с клавиатуры.

## 10. Технические требования
- Адаптив, быстрая загрузка (оптимизированные ассеты). Форма → цель Яндекс.Метрики «waitlist_signup»; UTM из URL. Без сторонних трекеров кроме Метрики.

## 11. Intent-сигнал (тест спроса) и измерение
- После заявки: «Что для тебя главное?» — варианты: «Чтобы считалось само, без ссылок» / «Чтобы выплату не зажали» / «Размер возврата» *(контроль)*; чекбокс «Готов(а) попробовать первым(ой) и оставить отзыв».
- **Критерий успеха:** CPS ≤ порога [[test-plan]]; распределение intent (что тянет — «без ритуала» или «доверие/ставка») — вход для этапа 9.

## 12. Что НЕ делать
- Не обещать процент / сумму / срок кешбэка; ничего против инвариантов. Без слов-табу. Цель — не установка приложения (его ещё нет). Без давления/таймеров.

## 13. Референсы и deliverables
- **Референсы:** «эталон на бренде» — `08-ads/tools/landing/` (генератор + design-system.css).
- **Deliverables:** макет (mobile + desktop), исходник, спецификация состояний формы (default/loading/success/error), экспорт ассетов, спека брейкпоинтов.
