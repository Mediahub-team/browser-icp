# ТЗ для дизайнера — лендинг «Кэшбэк Браузер» (ICP-03 Студенты)

> Техническое задание на дизайн **пред-продуктового лендинга**: продукт ещё НЕ запущен,
> цель страницы — **заявка в лист ожидания** (waitlist). Угол: «разберись в теме со
> ссылками, не выдумкой». Доминанта — **доверие к источникам / анти-галлюцинации**, не
> скорость. Кешбэк — вторая выгода (co-мотив C), отдельным блоком в варианте O8.

## 1. Контекст и цель
- **Продукт:** iOS-браузер с ИИ-ассистентом, который видит открытую страницу и ищет по
  вебу; ответы — с цитатой и ссылкой на конкретный абзац источника (анти-галлюцинации).
- **Стадия:** пред-запуск. **Единственная цель страницы:** заявка в лист ожидания.
- **Сегмент / мотив:** ICP-03 Студенты — мотив **A** (разобраться/понять) + co-мотив **C**
  (вернуть часть денег с покупок, тест co-C отдельным блоком).
- **Откуда трафик:** Yandex Direct (Поиск `utm_campaign=icp03_search` / РСЯ
  `icp03_rsya`), плюс VK / Telegram → метка кампании в UTM.

## 2. Аудитория и тон
- **Кто:** студенты и самообучающиеся 17–25, всё с телефона, дедлайны (курсовая / диплом /
  защита), тонкий бюджет. Боль: **ChatGPT выдумывает ссылки и факты, которых нет → «для
  диплома это опасно»**; перепроверка вручную съедает всю экономию времени.
- **Tone of voice:** свой, живой, без канцелярита; «механика, не интеллект» — объясняем
  *как устроено доверие к источнику*, а не хвалим «умную нейросеть».
- **Customer language (использовать дословно):** «помоги разобраться», «покажи, где это
  в тексте», «не хочу читать весь учебник», «ChatGPT бесплатный, чем вы лучше»,
  «сдать без страха спалиться на фейке», «где дешевле / с кешбэком».
- **Слова-табу (НЕ употреблять):** канцелярит, «образовательная экосистема», «нейро / LLM
  / агент / тул»; не давить на «сделаем ДЗ за тебя» / «решала»; не делать скорость главным
  обещанием (доминанта — источники).

## 3. Структура экранов (сверху вниз)
1. **Hero «со ссылками, не выдумкой»:** H1 = «Разберись в теме быстро — с проверяемыми
   источниками, а не выдумкой». Подзаголовок про механику: «ChatGPT выдумывает ссылки и
   факты, которых нет. Наш ИИ показывает цитату и место в тексте источника — видно, где это
   написано. Сдавай без страха спалиться на фейке.» + **CTA-кнопка** «Записаться в лист
   ожидания» (поле e-mail). В hero — мини-демо: ответ с подсвеченной цитатой и кликом на абзац.
2. **3 буллета ценности:**
   - «Каждый факт — с пруфом» — ответ привязан к источнику и конкретному абзацу, ничего «из головы».
   - «Покажи, где это в тексте» — видно цитату и место в источнике, не нужно перепроверять вслепую.
   - «Безопасно для диплома/курсовой» — битых и выдуманных ссылок нет, не спалишься на защите.
3. **Demo-блок «ответ + источник»:** слева вопрос студента по теме диплома/курсовой;
   справа ответ ИИ → кликабельная цитата в кавычках → раскрывается источник с
   **подсвеченным абзацем** и стрелкой «вот здесь в тексте». Контраст-плашка: «ChatGPT:
   ссылка ведёт в 404» vs «у нас: цитата + абзац источника».
4. **Доверие/честность:** снимаем «ChatGPT бесплатный, чем вы лучше» — он выдумывает, мы
   показываем источник. Честная граница: продукт ещё в листе ожидания; кешбэк — **без
   конкретных %/сроков**; не позиционируемся как «решала» (только разобраться, не списать).
5. **Форма заявки (waitlist):** поле e-mail + кнопка. После отправки — **intent-блок** (§4).
6. **Intent-блок** (см. §4) + лёгкое соц.доказательство (плейсхолдеры) + короткий футер.

## 4. Обязательные элементы конверсии
- **CTA** «Записаться в лист ожидания» повторяется минимум дважды (hero + после demo + в конце).
- **Форма waitlist:** e-mail (обязательно), без лишних полей.
- **Intent-сигнал после заявки** (ключ теста):
  - микро-вопрос «Что для вас главное?» — варианты: *проверяемые источники · разобрать тему
    быстро · безопасно для диплома · кешбэк с покупок* (последний — контрольный для дизамбигуации мотива);
  - чекбокс «Готов попробовать первым и оставить отзыв» (отделяет «любопытно» от «надо»).
- Никакого давления / таймеров / «осталось N мест».

## 5. Отдельный кешбэк-блок (тест co-C, только вариант O8)
- **Отдельный блок ниже демо** (включён только в O8-версии; в O7 скрыт): «И возвращай
  часть денег с покупок — кешбэк за обычные заказы (учебники, доставка, гаджеты). Вывод
  **от 100 ₽**, без холда 600 ₽.» Без процентов и сроков — только низкий порог.
- **Что проверяем:** усиливает ли co-мотив C конверсию или только разбавляет интент
  (O7 без блока vs O8 с блоком на одной аудитории). Если raw-signup растёт, но микро-вопрос
  показывает сдвиг в «кешбэк» и падение микро-коммитмента → **ложный спрос**, дисконтируем.
- **Визуально:** второстепенно по весу относительно hero/демо — кешбэк не должен перетягивать
  доминанту с источников.

## 6. Визуальный стиль
- Спокойная «учебная» палитра, чистая типографика; акцент-цвет — только на подсветке цитаты
  и кнопке CTA. Без кричащих распродажных цветов.
- **Mobile-first** (основной трафик — телефон), адаптив, крупные тапы.
- Иллюстрации показывают продукт честно: реальный механизм «цитата + абзац», без фото-стоков
  и без обещаний фич, которых нет.

## 7. Технические требования
- **Адаптив** (mobile-first), быстрая загрузка.
- **Форма → цель Яндекс.Метрики `waitlist_signup`** (для замера cost-per-signup); прокидываем
  UTM (`utm_source/medium/campaign/content`) из URL.
- Без сторонних трекеров кроме Метрики.

## 8. Что НЕ делать
- Не обещать связывающих цифр (кешбэк %/срок) — только порог вывода «от 100 ₽».
- Не использовать слова-табу; не делать установку приложения целью (продукта ещё нет).
- Не делать скорость главным посылом; не скатываться в «жадность» (кешбэк — вторая выгода).

## 9. Deliverables
- Макет (mobile + desktop), исходник, спецификация состояний формы (до / после заявки —
  с intent-блоком), две версии секции кешбэка (O7 скрыт / O8 показан), экспорт ассетов.
