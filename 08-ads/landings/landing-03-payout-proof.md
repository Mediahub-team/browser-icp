# ТЗ для дизайнера — лендинг offer-03-payout-proof / ICP-03

**Источники:** [[offer-03-payout-proof]] · [[icp-03-cashback-optimizers]] · [[product-description]] · [[market-landscape]] §6/§10.

> Пред-продуктовый лендинг (waitlist). Вариант под **снятие K3** (доверие к выплате) — для скептиков, видевших невыплаты агрегаторов. Честность: без связывающих цифр, ничего против инвариантов [[product-functionality]] §2.

## 1. Контекст и цель
- **Продукт (1 фраза):** iOS-браузер, возвращающий живые рубли за любую покупку через него.
- **Стадия:** пред-запуск. **Цель:** заявка в лист ожидания.
- **Сегмент / угол:** ICP-03 оптимизаторы-скептики — мотив контроль; **боль:** недоверие «обещают — а выплатят ли» (риск категории, [[market-landscape]] §10).
- **Откуда трафик:** Яндекс Директ РСЯ + Telegram → UTM.
- **Главный KPI:** CPS + intent; вторично — снижение оттока на шаге доверия.

## 2. Аудитория и тон
- **Кто и контекст:** обжёгся на «условия выполнены — кешбэк не пришёл»; «изменение» — сервис, которому можно верить.
- **Tone of voice:** спокойная надёжность, доказательно, без пафоса финтеха.
- **Customer language (дословно):** «пруф вывода покажи», «реальные выплаты», «условия выполнены — кешбэк не пришёл», «по оферте».
- **Слова-табу:** «гарантируем 100%», «мгновенно», точные суммы/сроки.

## 3. Описание и нарратив страницы
- **Главный вывод:** «Здесь видно каждый рубль кешбэка на каждом шаге, выплата по оферте — это не очередной сервис, который зажмёт».
- **Логика убеждения:** знакомая боль невыплаты → обещание прозрачности → доказательство (статус-трекер, лента выплат, оферта) → waitlist.

## 4. Структура секций
1. **Hero.** H1 (прозрачность выплаты) + подзаголовок (статусы + оферта) + CTA waitlist + мокап статус-трекера.
2. **Ценность — 3 буллета:** видно каждый шаг / по оферте, не на словах / лента реальных выплат.
3. **Demo.** Статус-трекер «Проверяем → Подтверждено → Выплачено» + лента выплат (помечена «образец» до накопления реальных).
4. **Доверие / честность.** Как устроена выплата (карта-партнёр, по публичной оферте, [[market-landscape]] §9); честная граница «бэкенд выплат достраивается — поэтому waitlist»; независимость.
5. **Форма waitlist** → intent (§11).
6. **Соц.доказательство.** Плейсхолдеры цитат + счётчик.
7. **Футер** с оферта/политика.

## 5. Копирайтинг
- **H1 (≤~60):** «Кешбэк, который реально приходит».
- **Подзаголовок (≤~120):** «Видно каждый рубль: начислили → подтвердили → вывели. По публичной оферте».
- **CTA-копи:** «Записаться в лист ожидания».
- **3 буллета:** «Прозрачный статус каждого начисления» · «Выплата по оферте, а не на словах» · «Лента реальных выплат».
- **Заголовок demo:** «Куда уходит ваш кешбэк»; шаги: «1. Проверяем покупку» · «2. Подтверждаем начисление» · «3. Выплачиваем на карту».
- **Блок доверия:** «Мы ещё на старте — поэтому лист ожидания, а не обещания. Когда откроем — выплата по публичной оферте, статус виден всегда».
- **Форма:** «Ваш e-mail»; микрокопи: «Без спама. Позовём, когда откроем доступ».
- **Спасибо:** «Вы в списке. Спасибо!»; **Ошибка:** «Проверьте e-mail».

## 6. Обязательные элементы конверсии
- CTA дважды; форма — только e-mail; intent-блок; без давления.

## 7. Визуальная иерархия и стиль
- Приоритет: H1 → CTA → статус-трекер → лента выплат. Акцентный цвет на CTA.
- Палитра: бренд-токены; настроение «надёжно, спокойно». Imagery: честный мокап трекера; лента выплат помечена как образец.

## 8. Адаптив и состояния
- Mobile-first; 360–430 / 768 / 1200+. Форма: default/focus/loading/success/error. CTA: default/hover/disabled.

## 9. Доступность
- Контраст ≥ AA; tap ≥ 44×44; focus-state; alt; семантика; клавиатура.

## 10. Технические требования
- Адаптив, быстрая загрузка. Форма → цель Метрики «waitlist_signup»; UTM. Без лишних трекеров.

## 11. Intent-сигнал и измерение
- После заявки: «Что для вас главное?» — «Чтобы выплату не зажали» / «Прозрачность статусов» / «Размер ставки» *(контроль)*; чекбокс «Готов(а) попробовать первым(ой)».
- **Критерий успеха:** CPS ≤ порога [[test-plan]]; **конверсия в заявку выше, чем у [[landing-03-no-ritual]]** — сигнал, что K3 решающий (изоляция T1↔T2).

## 12. Что НЕ делать
- Не обещать сумм/сроков/«100% гарантии». Не рисовать фейк-выплаты. Без слов-табу, без давления. Цель — waitlist, не установка.

## 13. Референсы и deliverables
- **Референсы:** `08-ads/tools/landing/` (эталон на бренде).
- **Deliverables:** макет (mobile + desktop), исходник, спецификация состояний формы, ассеты, брейкпоинты.
