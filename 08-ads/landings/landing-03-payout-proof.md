# ТЗ для дизайнера — лендинг offer-03-payout-proof / ICP-03

**Источники:** [[offer-03-payout-proof]] · [[icp-03-cashback-optimizers]] · [[product-description]] · [[market-landscape]].

> Пред-продуктовый лендинг (waitlist). Вариант под **снятие недоверия к выплате (K3)** — для тех, кто видел невыплаты у агрегаторов. Единственная цель — заявка в лист ожидания + intent-сигнал.
> ⚠️ **Честность (K3):** без связывающих цифр (процент / сумма / срок), ничего против инвариантов [[product-functionality]] §2. Лента выплат — образец до накопления реальных, не выдуманные суммы.
> 🛠 Все формулировки — через `russian-copywriting` (живой русский «ты», без канцелярита, ФЗ-38: без «гарантируем / 100 %»). Картинки — через `image` (§5.1).
> 🚫 Формулировки оффера / креатива не пробрасываем. Слоганы «кешбэк, который реально приходит», «видно каждый рубль», «по оферте, а не на словах» **не используем** — пишем заново; голоса клиента — в кавычках как сырьё.

---

## 1. Контекст и цель
- **Продукт (1 фраза):** iOS-браузер, который возвращает живые рубли за покупки, прошедшие через него.
- **Стадия:** пред-запуск. **Единственная цель страницы:** заявка в лист ожидания (e-mail).
- **Сегмент / угол:** ICP-03 оптимизаторы-скептики — мотив контроль; **боль:** недоверие «обещают, а выплатят ли» (риск категории, [[market-landscape]] §10).
- **Откуда трафик:** Яндекс Директ РСЯ + Telegram → метка кампании в **UTM**.
- **Главный KPI:** **CPS** + распределение intent; вторично — снижение оттока на шаге доверия.

## 2. Аудитория и тон
- **Кто и контекст:** обжёгся на «условия выполнены — кешбэк не пришёл»; разбирается, требует доказательств. «Изменение, которое покупают» — сервис, которому можно верить.
- **Tone of voice:** спокойная надёжность, доказательно, на равных; обращение **«ты»**. Без пафоса финтеха и восклицаний.
- **Customer language (как сырьё, в кавычках):** «пруф вывода покажи», «условия выполнены — кешбэк не пришёл», «обещают, а выплатят ли».
- **Слова-табу:** «гарантируем», «100 %», «мгновенно», «лучший / №1»; точные суммы / проценты / сроки.

## 3. Описание и нарратив страницы
- **Главный вывод (one takeaway):** «Видно, что с возвратом на каждом шаге, а условия закреплены офертой — это не очередной сервис, который тихо зажмёт.»
- **Логика убеждения:** знакомая боль невыплаты (узнавание) → статус виден на каждом шаге, выплата по оферте (обещание) → почему верить: статус-трекер, лента выплат, честно про пред-запуск (RTB) → лёгкое действие (waitlist).

## 4. Структура секций (сверху вниз) — что в каждой
1. **Hero.** H1 (прозрачность выплаты) + подзаголовок (статусы + оферта) + **CTA** «Записаться в лист ожидания» + честный мокап статус-трекера (концепты — §5.1).
2. **Ценность — 3 буллета.** Виден статус каждого начисления / деньги приходят на карту / условия — публичная оферта.
3. **Demo / «как это работает».** Статус-трекер «проверка → подтверждено → на карте» + лента выплат (помечена «образец»).
4. **Доверие / честность.** Как устроена выплата (карта-партнёр, публичная оферта, [[market-landscape]] §9); честная граница «бэкенд выплат достраиваем — поэтому лист ожидания»; независимость.
5. **Форма waitlist.** E-mail + кнопка; **после отправки** — intent-блок (§11).
6. **Соц.доказательство.** Плейсхолдеры цитат + счётчик (без выдуманных выплат).
7. **Футер.** Короткий; оферта / политика.

## 5. Копирайтинг (свежие формулировки, скилл `russian-copywriting`)
- **H1 (≤ ~60 симв.), 2 варианта:** «Видно, что с возвратом на каждом шаге» · «Возврат, который не теряется по пути».
- **Подзаголовок (≤ ~120 симв.):** «Начислили, подтвердили, вывели на карту — каждый шаг видно. Условия закреплены публичной офертой, а не строчкой в рекламе.»
- **CTA-копи (кнопка):** «Записаться в лист ожидания» *(повтор после demo)*.
- **3 буллета ценности:** «Виден статус каждого начисления» · «Деньги приходят на карту» · «Условия — публичная оферта, а не обещание».
- **Заголовок demo-блока:** «Куда идёт твой возврат»; подписи к шагам: «1. Проверяем покупку» · «2. Подтверждаем начисление» · «3. Выплачиваем на карту».
- **Блок доверия — заголовок + 1–2 фразы:** «Мы пока на старте — поэтому зовём в лист ожидания, а не обещаем горы. Когда откроем, проверишь сам: статус видно всегда, выплата по публичной оферте.»
- **Лейбл поля формы / плейсхолдер:** «Твой e-mail».
- **Микрокопи под формой:** «Напишем один раз — когда откроем доступ. Без рассылок.»
- **Состояние «спасибо»:** «Готово, ты в списке. Дадим знать, когда можно заходить.»
- **Текст ошибки формы:** «Кажется, в адресе опечатка — проверь.»
- **Intent-вопрос и варианты:** см. §11.

## 5.1 Картинки — варианты по местам (скилл `image`)
> 2–3 концепта на место. Сумм не показываем; лента выплат — «образец». WebP + фолбэк; hero/OG 1200×630 < 200 КБ; `width`/`height` заданы; ниже экрана `loading="lazy"`; alt у всех.

**Hero (визуал надёжности — «видно каждый шаг»):**
- A. Экран статус-трекера «проверка → подтверждено → на карте», подсвечен текущий шаг, **без сумм**. Чисто, контраст AA.
- B. Сдержанный блок со значком публичной оферты/документа, палитра «надёжно». Без золотых печатей и «100 %».
- C. Телефон с экраном статуса начисления, нейтральный фон, без стоковых лиц.

**Demo (механика, 3 шага):**
- A. Три плоских кадра-схемы «проверка → подтверждение → выплата на карту», иконки в бренд-цвете, без сумм.
- B. Один экран прототипа со статус-трекером и тонкой полосой прогресса. Реальный скриншот прототипа, не AI-интерфейс.

**Доверие / лента выплат:**
- A. Лента состоявшихся выплат с диапазонами, помеченными «образец» (до накопления реальных). Без конкретных сумм-обещаний.
- B. Блок «по оферте» со ссылкой на документ. Сдержанно, без галочек-гарантий.

> **Избегать везде:** золотые монеты и «дождь из денег», печати «100 %» и щиты-гарантии, стоковые улыбки, фиолетовые градиенты-клише, выдуманные суммы и чужие скриншоты выплат, AI-генерация интерфейса.

## 6. Обязательные элементы конверсии
- **CTA** дважды (hero + после demo). Форма — только e-mail. Intent-блок после заявки (§11). Без давления/таймеров.

## 7. Визуальная иерархия и стиль
- **Приоритет внимания:** H1 → CTA → статус-трекер → лента выплат. Акцентный цвет — на CTA.
- **Палитра/настроение:** бренд-токены; «надёжно, спокойно».
- **Imagery:** честный мокап трекера; лента выплат помечена «образец».

## 8. Адаптив и состояния компонентов
- **Mobile-first**, брейкпоинты 360–430 / 768 / 1200+.
- **Состояния формы:** default · focus · loading · success (intent-блок) · error. **CTA:** default · hover/active · disabled.

## 9. Доступность (a11y)
- Контраст ≥ WCAG AA; tap-target ≥ 44×44; видимый focus-state; alt у изображений; семантический HTML; навигация с клавиатуры.

## 10. Технические требования
- Адаптив, быстрая загрузка. Форма → цель Яндекс.Метрики «waitlist_signup»; UTM из URL. Без сторонних трекеров кроме Метрики.

## 11. Intent-сигнал (тест спроса) и измерение
- После заявки: «Что для тебя главное?» — варианты: «Чтобы выплату не зажали» / «Чтобы видеть статус начисления» / «Размер возврата» *(контроль)*; чекбокс «Готов(а) попробовать первым(ой) и оставить отзыв».
- **Критерий успеха:** CPS ≤ порога [[test-plan]]; **конверсия в заявку выше, чем у [[landing-03-no-ritual]]** — сигнал, что доверие (K3) решает (изоляция T1↔T2).

## 12. Что НЕ делать
- Не обещать сумм / сроков / «100 % гарантии». Не рисовать фейк-выплаты и чужие скриншоты. Без слов-табу, без давления. Цель — waitlist, не установка.

## 13. Референсы и deliverables
- **Референсы:** `08-ads/tools/landing/` (эталон на бренде).
- **Deliverables:** макет (mobile + desktop), исходник, спецификация состояний формы, экспорт ассетов, спека брейкпоинтов.
