# Промт для AI-генерации лендинга — ICP-02 Контент-читатели (мотив A, «суть без копипаста»)

> Готовый промт для генерации дизайна/кода. **Главный таргет — Claude (Artifacts)**;
> ядро универсальное (v0/Lovable/Bolt/любой LLM). Заполнено из [[offer-icp02-summary]],
> спека [[landings/icp02]], [[product-description]] и customer language
> [[icp-02-content-readers]]. Базовая версия — угол **O4 «суть из ленты»**;
> под O5/O6 меняй только H1, три буллета и приоритетный ответ интент-вопроса.

## Как пользоваться
1. При необходимости подставь вариант O5/O6 (см. низ файла). 2. Вставь блок ПРОМТ
целиком в Claude. 3. Получишь адаптивный лендинг одним файлом. 4. Проверь по чек-листу.

---

## ПРОМТ (копировать целиком)

```
Ты — продуктовый веб-дизайнер и фронтендер. Сделай ОДНОСТРАНИЧНЫЙ адаптивный лендинг
(mobile-first) одним самодостаточным файлом: HTML + Tailwind (CDN) + минимум JS.
Никаких внешних зависимостей кроме Tailwind CDN. Верни один файл, готовый открыть в браузере.

КОНТЕКСТ ПРОДУКТА (пред-запуск, продукт ещё не вышел):
iOS-браузер, в котором ИИ видит открытую страницу и делает её суть прямо на месте —
без копипаста, без переключения вкладок и без логина в чат. Ведущая ценность для этой
аудитории — скорость и «дай суть», а не «умный ИИ».
ЧЕСТНОСТЬ (обязательно соблюдать, не приукрашивать): продукт ещё готовится, это запись
в лист ожидания, а не готовое приложение; не обещай конкретных цифр кешбэка/сроков;
не утверждай, что «умнее ChatGPT» — отстройка строится на механике, а не на интеллекте.

ЦЕЛЬ СТРАНИЦЫ: единственное целевое действие — оставить заявку в ЛИСТ ОЖИДАНИЯ (e-mail).
Продукт ещё не запущен — не предлагай «скачать приложение».

АУДИТОРИЯ И ТОН: ICP-02, контент-читатели, мотив A. Это люди, которые тонут в контенте
с телефона (10–30 Telegram-каналов, новости, лонгриды) и систематически НЕ пользуются ИИ.
Тон — простой, разговорный, «механика, а не интеллект»: открыл → тап → суть прямо здесь.
Спокойно, без хайпа и без техножаргона.
ЯЗЫК (вставь дословно в тексты): «дай суть», «о чём это если коротко», «нет времени читать»,
«копится непрочитанное», «сохранил — будто прочитал», «сто непрочитанных лонгридов».
СЛОВА-ТАБУ (не употреблять ни в каком виде): нейро, нейросеть, LLM, агент, тул, тул-юз,
промпт. Не сравнивай с ChatGPT в духе «мы умнее» — только механика «ИИ уже открыт
на этой странице, копировать ничего не надо».

СТРУКТУРА (сверху вниз):
1. Hero: H1 = «Десять каналов за пять минут. Тап — и суть, без копипаста.»;
   подзаголовок = «ИИ работает прямо на открытой странице. Не надо копировать текст,
   переключать вкладки или логиниться в чат — суть появляется там же, где ты читаешь.»;
   кнопка CTA «Записаться в лист ожидания».
2. Три буллета ценности:
   - «Пробеги ленту канала за минуту — тап по посту, и суть без скролла.»;
   - «Ничего не копируешь и никуда не пересылаешь — ИИ читает прямо открытый пост.»;
   - «10–30 каналов? Лови главное за день, не утонув в скролле.».
3. Demo-блок: схематично покажи «открыл пост → ОДИН ТАП → 3 буллета сути выезжают поверх
   ТОЙ ЖЕ страницы» (мокап экрана телефона, без фото-стоков и без «роботов»); подпись
   «без копипаста»; кнопка «Посмотреть, как это работает».
4. Блок доверия: «Суть привязана к месту в тексте — видно, откуда взято»; честная граница —
   «продукт ещё готовится, записываем в лист ожидания».
5. Форма waitlist: поле e-mail + кнопка. ПОСЛЕ отправки показать intent-блок:
   - вопрос «Что для вас главное?» с вариантами: «суть из ленты каналов»,
     «суть рабочего документа до созвона», «разгрести сохранёнки»,
     «кешбэк за покупки» (контрольный), «другое»;
   - чекбокс «Готов попробовать первым и оставить отзыв».
   (JS: по сабмиту прятать форму, показывать intent-блок и «спасибо»; данные никуда
   не шлём — заглушка.)
6. Лёгкое соц.доказательство (плейсхолдеры: цитата «Сохранил сто статей — не прочитал
   ни одной. Дайте суть» + счётчик ожидающих) + короткий футер.

ДИЗАЙН: mobile-first, чистая крупная типографика, много воздуха, один акцент-цвет на
тапе/кнопке — ощущение «секунда и готово». Без таймеров, без «осталось N мест», без
давления. Доступность (контраст, размеры тапа). Семантический HTML.

ИЗМЕРЕНИЕ (заглушки, без реальных ключей): предусмотри место под цель Метрики
«waitlist_signup» (data-атрибут на форме) и чтение UTM из URL (utm_source/medium/
campaign/content/term).

Верни ТОЛЬКО код одного файла.
```

## Варианты под O5 / O6 (заменить H1 + буллеты + приоритет интента в промте)
- **O5 «Суть из простыни / до созвона»:** H1 = «Суть из простыни — до созвона.
  Без копипаста наружу.»; буллеты — «За минуту владеешь длинным материалом — суть и
  ключевые цифры в один тап» / «Ничего не копируешь во внешний чат — важно, где ChatGPT
  под запретом» / «Источник под рукой: сошлёшься на абзац, а не на пересказ»; усилить
  доверие «текст не уходит наружу».
- **O6 «Разгрести сохранёнки»:** H1 = «Сто непрочитанных лонгридов? Суть каждой —
  в один тап. Без копипаста.»; буллеты — «Сто сохранёнок → суть каждой в один тап» /
  «Открыл из избранного — ИИ читает прямо страницу, переносить ничего не надо» /
  «Закрой вину за непрочитанное: кладбище превращается в “прочитано”»; в demo — счётчик
  «разобрано N из 100».

## Чек-лист после генерации
- [ ] CTA = «лист ожидания», нет «скачать приложение».
- [ ] Нет слов-табу (нейро/LLM/агент/тул/промпт); использован customer language.
- [ ] Отстройка через механику «ИИ уже открыт на странице», без «умнее ChatGPT».
- [ ] Есть intent-блок после заявки (микро-вопрос с контрольным «кешбэк» + чекбокс).
- [ ] Demo показывает «тап → суть на ТОЙ ЖЕ странице», без стоков/роботов.
- [ ] Mobile-first, адаптивно, без давления/таймеров.
