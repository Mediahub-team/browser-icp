# ТЗ для дизайнера — лендинг ICP-01 AI-power-users (мотив A, «без копипаста»)

> Техническое задание на дизайн **пред-продуктового лендинга**: продукт ещё не запущен,
> цель страницы — **заявка в лист ожидания** (waitlist). Дешёвый эксперимент (kill-fast):
> меряем притяжение обещания, а не использование. Источники: [[landings/icp01]],
> [[offer-icp01-power]], [[icp-01-ai-power-users]], [[product-description]].

## 1. Контекст и цель
- **Продукт:** iOS-браузер с ИИ, который видит ту страницу, что открыта, и работает по всему
  вебу (на лендинге ТОЛЬКО эта механика; кешбэк/шопинг/маркетплейсы НЕ упоминаем).
- **Стадия:** пред-запуск. **Единственная цель страницы:** заявка в лист ожидания.
- **Сегмент / мотив:** ICP-01 AI-power-users — мотив **A** (контроль/эффективность).
- **Откуда трафик:** Yandex Direct (Поиск `icp01_search` / РСЯ `icp01_rsya`) → метка в UTM.

## 2. Аудитория и тон
- **Кто:** ранние адопторы ИИ, живут в ChatGPT/Claude ежедневно (продакты, IT, аналитики,
  ресёрчеры). Боль — **механика**: копипаст текста/URL в чат, «ИИ не видит мой экран»,
  особенно на мобайле, в PDF и за логином. Боль «понять» у них уже закрыта ChatGPT.
- **Tone of voice:** простой, по делу, «механика, а не интеллект». Как пишут гики друг другу,
  без маркетингового шума. Никакого пафоса и обещаний «революции».
- **Customer language (использовать дословно):** «достало копипастить в чат»,
  «а можешь прямо по этой странице?», «он что, видит что у меня открыто?»,
  «курьер между вкладкой и чатом», «4 ссылки → таблица суть / риск / что делать».
- **Слова-табу (НЕ употреблять):** «умный ассистент / помощник», «нейросеть нового
  поколения», «революционный», «кешбэк», «скидки», «шопинг», «маркетплейс», «LLM / агент»,
  казёнщина. (Любой намёк на «ещё один умный чат» → субституция текущим ChatGPT.)

## 3. Структура экранов (сверху вниз)
1. **Hero (механика «без копипаста»):**
   - **H1:** «Хватит быть курьером между вкладкой и чатом».
   - **Подзаголовок:** «ИИ работает с открытой страницей и вебом — спрашиваешь прямо на ней.
     Без копипаста и переключения вкладок».
   - **CTA-кнопка:** «Записаться в лист ожидания».
   - **Визуал hero:** before/after — слева перетаскивание текста из вкладки в чат,
     справа ответ ИИ поверх той же страницы (стрелок нет).
2. **3 буллета ценности (только механика):**
   - «Не копируешь — ИИ видит страницу.» Открыл → спросил → ответ по тому, что на экране.
   - «Работает там, где копировать нельзя: мобайл, PDF, контент за логином.»
   - «4 вкладки → одна таблица „суть / риск / что делать“» — мульти-таб синтез без ручной сводки.
3. **Demo-блок (два сценария):**
   - **Демо 1 «не копируешь — ИИ видит страницу» (O9):** короткий цикл before/after.
     Before: выделить → переключиться в ChatGPT → вставить → ждать. After: открыл страницу →
     спросил → ответ по ней. Подпись: «ИИ читает ту самую страницу, что открыта — даже PDF / за логином».
   - **Демо 2 «мульти-таб синтез» (O10):** 4 открытые вкладки → один тап → таблица
     «суть / риск / что делать» со ссылками; колонка «риск» подсвечивает расхождения.
     Подпись: «4 ссылки → сводная таблица, без копипаста между вкладками».
4. **Честность / граница:** «Браузер пока в разработке, открываем доступ по списку. Без
   обещаний цифр и сроков.» Без упоминания кешбэка/маркетплейс-фич (этого угла на странице нет).
5. **Форма заявки (waitlist):** поле e-mail + кнопка. После отправки — **intent-блок** (см. §4).
6. **Соц.доказательство:** плейсхолдер цитат «таких же гиков» + счётчик ожидающих
   (заменить на реальные). Без накрутки и фейков.
7. **Футер:** короткий, без отвлекающих ссылок.

## 4. Обязательные элементы конверсии
- **CTA** повторяется минимум дважды (hero + после demo).
- **Форма waitlist:** e-mail (обязательно), без лишних полей.
- **Intent-сигнал после заявки** (ключ теста):
  - микро-вопрос «Что для вас главное?» — варианты:
    *спросить прямо на странице* / *страницы за логином и PDF* /
    *свести несколько вкладок в таблицу* / *просто интересно* («просто интересно» = маркер
    любопытства / низкого интента);
  - чекбокс «Готов попробовать первым и оставить отзыв».
  - **НЕ предлагаем** «кешбэк» как вариант — этого угла на лендинге нет вовсе.
- Никакого давления / таймеров / «осталось N мест».

## 5. Визуальный стиль
- Чистый, быстрый, «инструментальный» — как продуктивити-тула для гиков. Светлая база,
  один акцентный цвет, моноширинные акценты уместны. Без стоковых лиц и «корпоративной» графики.
- Мобайл-first (основной трафик — телефон), адаптив.
- Иллюстрации демонстрируют продукт честно (показываем механику «ИИ видит страницу»,
  не обещаем того, чего нет).

## 6. Технические требования
- **Адаптив** (mobile-first), быстрая загрузка.
- **Форма → цель Яндекс.Метрики «waitlist_signup»** (для замера CPS); прокидываем UTM
  (`utm_source/medium/campaign/content`) на отправке.
- Без сторонних трекеров кроме Метрики.

## 7. Что НЕ делать
- Не обещать связывающих цифр/сроков, которых продукт может не вытянуть.
- Не использовать слова-табу; не называть продукт «умным ассистентом».
- Не упоминать кешбэк/шопинг/маркетплейсы.
- Не делать установку приложения целью (продукта ещё нет) — только лист ожидания.

## 8. Референсы и deliverables
- **Референсы:** чистые waitlist-лендинги dev-тулзов (linear-подобный минимализм),
  before/after демо в духе продуктовых тизеров.
- **Deliverables:** макет (mobile + desktop), исходник, спецификация состояний формы
  (до / после заявки → intent-блок), экспорт ассетов demo-блоков.
