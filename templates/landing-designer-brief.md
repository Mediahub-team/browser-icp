## 3. Структура экранов (сверху вниз)
1. **Hero:** заголовок (главный посыл оффера) + подзаголовок (механика/обещание) + **CTA-кнопка** «Записаться в лист ожидания».
2. **3 буллета ценности** — <из спека лендинга>.
3. **Demo-блок:** <визуальное «как это работает» — скрин/анимация/иллюстрация>.
4. **Доверие/честность:** <напр. «глубокий разбор пока на Ozon», «на чём вердикт», независимость>.
5. **Форма заявки (waitlist):** поле e-mail + кнопка. После отправки — **intent-блок** (см. §4).
6. **Соц.доказательство:** плейсхолдер цитат + счётчик ожидающих (заменить на реальные).
7. **Футер:** короткий, без отвлекающих ссылок.

## 4. Обязательные элементы конверсии
- **CTA** повторяется минимум дважды (hero + после demo).
- **Форма waitlist:** e-mail (обязательно), без лишних полей.
- **Intent-сигнал после заявки** (ключ теста):
  - микро-вопрос «Что для вас главное?» — варианты: <под оффер + контрольный>;
  - чекбокс «Готов попробовать первым и оставить отзыв».
- Никакого давления/таймеров/«осталось N мест».

## 5. Визуальный стиль
- <палитра/настроение: для S — спокойный, надёжный; для A — чистый, быстрый>.
- Мобайл-first (основной трафик — телефон), адаптив.
- Иллюстрации демонстрируют продукт честно (не обещают того, чего нет).

## 6. Технические требования
- **Адаптив** (mobile-first), быстрая загрузка.
- **Форма → цель Яндекс.Метрики «waitlist_signup»** (для замера CPS); прокидываем UTM.
- Без сторонних трекеров кроме Метрики.

## 7. Что НЕ делать
- Не обещать связывающих цифр (кешбэк %/срок), которых продукт может не вытянуть.
- Не использовать слова-табу. Не делать установку приложения целью (продукта ещё нет).
