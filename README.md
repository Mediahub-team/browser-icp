# browser-icp

Исследовательский репозиторий для **Кэшбэк Браузера**: генерация ICP (Ideal Customer
Profile), детальные портреты пользователей, кастдев/проблемные интервью, их прогон на
синтетических респондентах, интерпретация, офферы и тест офферов через таргет-рекламу.

Методология — на основе AI-подхода к CustDev (Market Echo / delve.ai / seohead):
генерация ICP-кандидатов из контекста продукта → скоринг по fit-confidence →
синтетические респонденты по fit-кольцам → six-pillar интервью → анализ → офферы →
реклама → выводы «какой оффер на какую аудиторию заходит лучше».

> Полный план и принципы — в [`PLAN.md`](PLAN.md).

|---|---|---|

## Как пользоваться

Этапы идут последовательно, каждый кормит следующий. В каждой папке — `README.md`
с инструкцией, шаблоном и промптом для генерации. Проходим этап → кладём артефакты
рядом → переходим к следующему. Стрелки обратной связи: результаты рекламы (этап 9)
уточняют гипотезы (этап 1) и офферы (этап 7); зашедшие офферы (этап 7) предлагают новые
возможности в функциональность (этап 0) — межитерационно, см. [`PLAN.md`](PLAN.md) §3.

## Версионирование и ветки

Каждый прогон/результат фиксируется отдельным коммитом по формату `[s<N>] …`, чтобы
всегда можно было откатиться в нужную точку пайплайна. Четыре ортогональные оси изменений:
развилки по **углу позиционирования** — `cycle/<vision>`; **эволюция функциональности** между
итерациями (впитывание фич из офферов) — `version/<version-name>`; развилки внутри этапа (мотив,
гайд, офферная стратегия) — `s<N>/<slug>`; отдельные **прогоны** этапа — суффиксом `-v<x>`.
Сравниваются диффом downstream-папок. Канон — в `main`. Поверх форков идёт пятая, ортогональная
операция — **синхронизация меты**: структурное (шаблоны, методология, инструкции) едино во всех
ветках и проливается из `main` в `cycle/*`, контент не трогается. Полные правила, формат коммитов
и рабочий цикл — в [`BRANCHING.md`](BRANCHING.md).

## Obsidian-ваулт

Репозиторий можно открыть как **Obsidian-ваулт** (*Open folder as vault* → `browser-icp/`):
граф связей и бэклинки показывают, **откуда что берётся** по пайплайну, а Dataview собирает
авто-таблицы (ICP по мотивам, персоны по кольцам, прогоны). Конвенция (frontmatter, вики-ссылки,
теги, трассировка) и проверка формата — в [`VAULT.md`](VAULT.md). Валидатор: `python3 tools/check-vault.py`.
